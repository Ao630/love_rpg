# 恋愛RPG -恋愛マスターに俺はなる！-

RPG × 乙女ゲーム × 連打ゲーム。「アタックする！」を連打して好感度を上げ、告白成功率が下がる前に「告白しろ！！！」を押す、ブラウザ用の静的ゲームです。
HTML・CSS・JavaScript だけで動き、ビルドやサーバーは不要です(GitHub Pages でそのまま公開できます)。

> 画像・音声・セリフ・シナリオは **まだ提供されていないため、すべて空欄のテンプレート** になっています。
> 素材が空でもエラーにならず、画面のレイアウトと基本のゲーム進行を確認できます(キャラクター画像は「未設定」の枠、セリフ欄は空欄で表示されます)。

---

## 1. 遊び方

1. タイトルで「スタート」。
2. 「アタックする！」を押して左の好感度ゲージをためる(半分を上回ると画像・セリフ・音声が後半用に切り替わる)。
3. ゲージがMAXになると、告白成功率が表示され「告白しろ！！！」ボタンが現れる。成功率は「アタックする！」で上がり、時間とともに下がる。
4. 「告白しろ！！！」を押すと、そのときの成功率で成否を一度だけ判定。
5. 通常ステージ2人 → ラスボスの順に成功するとクリア。失敗すると敗北画面。「降参」でタイトルに戻る。
6. 右上のストップウォッチ(RTA)は、スタートからクリアまでを計測する。

## 3. 画面遷移

```
タイトル ─スタート→ 導入の独白 → ステージ移動 → 相手との会話 → 戦闘 → 戦闘後の会話
                                                                      │
                          ┌──────────────── 告白失敗 ─────────────────┤
                          ▼                                           │告白成功
                       敗北画面 → タイトル             通常ステージ → ステージ移動(次の相手へ)
                                                       ラスボス     → エピローグの会話 → クリア画面 → タイトル
戦闘中の「降参」 → タイトル
```

- 通常ステージ2人は、ゲーム開始のたびに登録キャラから**重複なくランダム**に選ばれ、登場順も決まります。ラスボスは固定です。
- ストップウォッチは「スタート」で開始し、**告白失敗の時点**、または**ラスボス成功の時点**で停止します(クリア画面の最終タイムはこの値)。
- ページ遷移の状態は `sessionStorage` で受け渡します。戻る操作やURL直打ちで不正な画面を開いても、現在の進行に合った画面へ自動で戻されます。
- 戦闘画面を再読み込みすると、そのステージの好感度は0からやり直しです(タイマーは継続)。

## 4. 素材・データの追加方法

素材がない状態でも動きます。素材を入れると、その分だけ表示・再生されます。

### キャラクターを登録する(`js/data/characters.js`)

1. 画像を `assets/images/`、音声を `assets/audio/` に置く。
2. `js/data/characters.js` の `normal`(通常ステージ)または `boss`(ラスボス)のブロックに、ファイルのパスや文章を書く。

```js
{
  id: 'girl01',                                   // 重ならない英数字のID(必須)
  name: '名前',
  images: { normal: 'assets/images/girl01-1.png', // 通常時の画像
            high:   'assets/images/girl01-2.png' },// 好感度が半分を超えた後の画像
  voices: { normal: ['assets/audio/girl01-v1.mp3'],                       // アタックのたびにランダムで1つ再生
            high:   ['assets/audio/girl01-v2.mp3', 'assets/audio/girl01-v3.mp3'] },
  lines:  { normal: ['セリフ1'], high: ['セリフ2', 'セリフ3'] },          // アタックのたびにランダムで1つ表示
  talk:   { before: ['戦闘前の会話1ページ目', '2ページ目'],               // 1要素 = 1タップで表示される1ページ
            afterSuccess: ['告白成功後の会話'],
            afterFail: ['告白失敗後の会話'] }
}
```

- 通常ステージの女の子を増やすときは、`normal` 配列に同じ形のブロックを追加します(`id` は他と重ねない)。2人以上登録してください。
- ラスボスは `boss` に書きます。`talk.epilogue` は「ラスボス成功後、クリア画面の前の会話」です。
- 画像は `.png / .jpg / .webp`、音声は `.mp3`(または `.ogg / .wav`)を想定しています。
- 空欄の項目は、画像なら「未設定」の枠、セリフや音声ならスキップ、会話なら空白の1ページ(1タップで進む)として扱われます。

### 背景画像・導入の独白・敗北コメント

- 背景画像: `js/config.js` の `assets.backgrounds`(`classroom` = 戦闘・会話、`intro`、`map`)にパスを書く。
- 導入の独白: `js/data/scenario.js` の `intro`(1要素 = 1ページ)。
- 敗北コメント: `js/data/scenario.js` の `defeatComments`(表示のたびにランダムで1つ)。

### 必要な素材の一覧(未提供)

| 種類 | 内容 | 推奨形式 |
| --- | --- | --- |
| キャラ画像 | 通常ステージの女の子(複数人)とラスボスの、通常時・好感度が半分を超えた後の2種類 | PNG(透過)/ WebP |
| 背景画像 | 教室(戦闘・会話画面)。必要なら導入・ステージ移動用 | JPG / PNG / WebP |
| 音声 | キャラごとの音声(各3つ程度を想定) | MP3 |
| セリフ | キャラごとの、アタック時のセリフ(通常時・後半) | テキスト |
| 会話 | 戦闘前・戦闘後(成功/失敗)・ラスボスのエピローグ | テキスト |
| 導入の独白 | ゲーム開始直後の文章 | テキスト |
| 敗北コメント | 敗北画面に出す一言(複数) | テキスト |
| キャラ名・設定 | 名前など | テキスト |

## 5. ゲームバランスの調整(`js/config.js`)

数値はすべて `js/config.js` に集約しています。**下表の値は原案に数値がないため、仮の初期値です。**

| 項目 | 設定名 | 仮の初期値 |
| --- | --- | --- |
| 好感度の最大値 | `affection.max` | 100 |
| アタック1回の好感度の増加量 | `affection.gainPerAttack` | 5(20回でMAX) |
| 後半に切り替わる境目 | `affection.highThresholdRatio` | 0.5(半分を上回ったら) |
| 好感度MAX時の成功率 | `confession.initialRate` | 10(%) |
| アタック1回の成功率の増加量 | `confession.gainPerAttack` | 4(%) |
| 成功率の自然減少 | `confession.decayPerSecond` | 8(%/秒) |
| 成功率の上限・下限 | `confession.max` / `confession.min` | 100 / 0 |

成功率が r% のとき、成功する確率は r% です(0%は必ず失敗、100%は必ず成功)。画面に出ている整数の数字がそのまま判定に使われます。

## 6. ローカルでの起動

どちらでも動きます。

- **一番かんたん**: `index.html` をブラウザで開く(ダブルクリック)。
- **簡易サーバー(おすすめ)**: プロジェクトのフォルダで次を実行し、`http://localhost:8000/` を開く。
  ```
  python3 -m http.server 8000
  ```

## 7. GitHub Pages での公開手順

1. GitHub で新しいリポジトリを作る(例: `koi-rpg`)。
2. このフォルダの中身(`index.html` が一番上の階層に来るように)をすべてリポジトリへアップロードする。
   ```
   git init
   git add .
   git commit -m "恋愛RPG"
   git branch -M main
   git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
   git push -u origin main
   ```
3. GitHub のリポジトリで **Settings → Pages** を開く。
4. **Build and deployment** の Source を **Deploy from a branch** にし、Branch を `main` / `/ (root)` にして Save。
5. 数分後、`https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される。

すべてのファイル参照は相対パスなので、`/<リポジトリ名>/` というサブパス配下でもそのまま動きます。APIキーなどの秘密情報や、外部サービスへの依存はありません。

## 8. テスト

```
node tests/logic.test.js
```

好感度の上限、半分での切り替え、MAXでの移行、成功率の増減と上限・下限、告白判定が一度だけ実行されること、キャラの重複なし抽選、ラスボス固定、全画面の遷移(成功/失敗/降参/不正遷移)、ストップウォッチの停止と整形を検証します(Node.js が必要)。

## 9. 仕様確認が必要な項目(仮の動作で実装しています)

原案で決まっていない部分は、勝手に確定せず、いまは次の仮の動作にしてあります。決まったら教えてください。

1. 好感度・告白成功率の数値(上の表)。
2. ストップウォッチの表示形式: Figmaの「00:12:34」に合わせ「分:秒:1/100秒」。クリア画面の「00.00」とどちらの形式にするか。
3. 戦闘画面の「ステージ 1-3」の意味: 「第1ステージ(全3ステージ中)」として表示。
4. 告白失敗時: 戦闘後の会話を挟んでから敗北画面へ。タイマーは告白失敗の時点で停止。
5. ラスボス成功後: 戦闘後の会話 → エピローグの会話 → クリア画面(原案の「ラスボスとの会話 → クリア画面」)。
6. 会話画面で使うキャラ画像: 通常時の画像(`talkImageAfterBattle` で後半用の画像に切り替え可能)。
7. 敗北・クリア・ステージ移動・導入の画面はFigmaにデザインがないため、タイトル/会話画面に合わせた仮のレイアウト。
8. 色・寸法はFigmaのスクリーンショットから目視で推定した値(Figmaの正確な値は取得できていません)。
9. 好感度MAX後も「アタックする！」は押せて、成功率を上げる動作になる(原案に従う)。
10. 音声・BGM・効果音の再生タイミング(BGMや効果音は現在なし。アタック時の音声のみ)。
